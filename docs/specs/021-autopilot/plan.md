# Plan 021: Autopilot from idea to finished book

**Spec:** spec.md (Approved)

## Context
Every stage already runs as a studio job (`video_pipeline/studio/jobs.py`: one `JobRunner`, one job at a time, Stop = SIGTERM→SIGKILL to the job's process group, stale `running` records become `interrupted` on restart). Spec 019 adds the `build` (editions) stage and `books.editions_state`; spec 016 the `paint` stage and `books.paint_state`; spec 018 changes nothing here. Autopilot chains these stages after an idea is chosen and writes the two human marks itself, recorded as automatic.

Working tree: on top of the uncommitted 012–020 work. Touch only the files named here; commit nothing unless asked. TDD; tests use the `Commands` / `StoryCommands` fakes and the `Studio` helper and never run real Codex, Orpheus, painting, the cut models, FFmpeg renders or the book builder.

## Design choice: one autopilot CLI process run as one studio job

`python -m video_pipeline.autopilot --book <slug> | --draft <id> --root R` runs the stages in order, each as a child process with exactly the argv `jobs.stage_command` builds (FR-1), and is itself started by the studio as one job, stage `autopilot`.

Why not a background thread in the studio that starts the next job when one ends:
- **One-job rule (FR-3):** between two jobs a thread leaves a gap in which a manual start (or another autopilot) gets in. As one job the runner is busy for the whole run, so every manual button is refused as busy with no new code.
- **Stop (AC-1.3):** the runner's existing Stop signals the job's process group; the child stage is in that group, so the current stage and the run end together and nothing later can start. A thread would need its own cancel flag racing the job end.
- **Restart (AC-4.3):** the runner already marks a stale `running` job `interrupted` and kills a recognisable orphan (`video_pipeline` is in its command line). No thread state to rebuild, and nothing resumes by itself.
- **Logs (AC-4.1):** the children inherit the job's stdout, so the job log shows each stage's own output under a `== autopilot: <stage> ==` header, including the failing stage's reason.
- Cost: per-stage "running" on the book page is derived from the run-state file instead of the job's stage name (Phase 3).

Run state (FR-2): `build/studio/autopilot/<slug>.json` (`draft-<id>.json` until the book exists), written atomically:
`{book, draft, job_id, state: running|finished|failed|stopped, stage, reason, started_at, updated_at, finished_at, by: "autopilot", steps: [{stage, result: skipped|done|failed, at}]}`. `job_id` comes from a new `KIDDO_JOB_ID` variable the runner puts in every job's environment. The studio shows a `running` file whose `job_id` is not the current job as `interrupted` (AC-4.3, also covers SIGKILL).

Automatic marks use `"by": "autopilot"`: in `episode/reviewed.json` and in `build/audio/status.json`. A person's later Mark as reviewed / Approve overwrites them without `by`.

Decisions recorded here (not in the spec): pictures or a script that are only stale from a changed blueprint (spec 011) are not regenerated by autopilot (that costs a full repaint or overwrites hand edits); the run stops at that stage with the reason and the button to use. An existing, unreviewed script is marked reviewed automatically (safety rests on the voice CLI's `validate_script` and kid-safety terms, as the spec says).

### Phase 2: The autopilot CLI
**Implements:** FR-1, FR-2, FR-4 · **Satisfies:** AC-1.1 (create after the draft), AC-2.1, AC-2.2, AC-3.3, AC-4.1, AC-4.2 · **Files:** `video_pipeline/autopilot.py` (new), `tests/test_autopilot.py` (new)

Goal: one command that starts at the first unfinished stage, runs each in order, skips what is done and up to date, writes the marks, and stops at the first failure with the stage and reason.

- Steps, each `(name, needs(paths, book) -> str | None, act)`; `needs` returns why the step must run, `None` to skip (AC-2.2). States come from the studio's own file-derived functions in `video_pipeline/studio/books.py` (no web code there):

| step | runs when | act |
|---|---|---|
| `paint` | `paint_state` has `missing` (stale-only → stop with reason) | child `stage_command("paint")` |
| `plan` | a page with a picture has no current plan (`plan_state` missing/stale/invalid) | child `stage_command("plan")` |
| `cut` | a page with a current plan is not cut (`page_animation` rows) | child `stage_command("cut")` |
| `script` | no script (blueprint-stale script → stop with reason) | child `stage_command("script")` |
| `review` | `reviewed_mark` is None | `mark_reviewed(..., by="autopilot")` |
| `voices` | `_voices_state` is `not_started` / `out_of_date` | child `stage_command("voices")` |
| `approve` | `_voices_state` is `needs_review` | `sv.approve(..., by="autopilot")` |
| `render` | `_video_state` is not `done` | child `stage_command("render")` |
| `build` | `editions_state` (spec 019) is not `done`; `blocked` → stop | child `stage_command("build")` |

- `run(paths, slug, *, run_child=_run_child, now=_now) -> int`: for each step, re-check `needs` (so a resumed run starts at the first unfinished stage, AC-4.2), print `== autopilot: <step> ==`, act; a child exit ≠ 0 or a raised `StudioError` / `ApproveError` / `ConfigError` → state `failed`, `stage`, `reason` (`"<label> failed (exit code N); see the log"` or the error text), return 1 (AC-4.1). After a successful act, `needs` must now be None, else fail with "<step> finished but is still not done" (guards against loops). All steps passed → `finished`, `finished_at`, return 0.
- AC-3.3: the voices CLI raises `LineFailed` and exits 1 with every failing line named in its stderr (already in the log); autopilot stops at `voices` and never reaches `approve`. `approve` also refuses (`ApproveError`) anything not valid for the current script and settings.
- `--draft ID`: child `stage_command("blueprint", ID)` (design + `--then-book`), then the draft must be `ready` (else fail at `story` with the draft's problems), then `DraftStore(root).create_book(ID)` (`DraftError` → fail at `create`), the run file moves to `<slug>.json` (with `draft: ID`), and the book steps follow (AC-1.1).
- `_run_child(cmd)`: `subprocess.run(cmd, check=False, stdin=DEVNULL)` with inherited stdout/stderr (argv list, never a shell). SIGTERM handler: write `stopped` with the current stage, `raise SystemExit(143)` (the child got the same signal from the group).
- Tests (fake `run_child` that writes each stage's outputs, using `tests/render_helpers.make_world` / `tests/helpers.make_root`): `test_steps_run_in_spec_order_from_an_empty_book`; `test_done_steps_are_skipped`; `test_finished_book_runs_nothing_and_finishes`; `test_failed_child_stops_with_stage_and_reason_and_runs_nothing_later`; `test_resume_starts_at_the_first_unfinished_stage`; `test_review_and_approval_are_written_by_autopilot`; `test_voices_failure_never_approves` (AC-3.3); `test_approve_error_stops_at_approve`; `test_step_still_needed_after_success_fails`; `test_stale_blueprint_pictures_stop_with_reason`; `test_blocked_editions_stop_with_missing_pictures`; `test_draft_run_writes_story_then_creates_book_then_paints`; `test_draft_not_ready_stops_at_story`; `test_sigterm_marks_the_run_stopped`; `test_children_use_stage_command_argv`; `test_run_state_file_is_written_atomically_with_by_autopilot`.

### Phase 3: Autopilot on the book page
**Implements:** FR-2, FR-3 · **Satisfies:** AC-1.2, AC-1.3, AC-2.3, AC-4.1, AC-4.2, AC-4.3 · **Files:** `video_pipeline/studio/jobs.py`, `video_pipeline/studio/books.py`, `video_pipeline/studio/app.py`, `video_pipeline/studio/templates/book.html`, `tests/test_studio_autopilot.py` (new), `tests/test_studio_jobs.py`

Goal: Run autopilot / Stop / resume from the book page, with the run's stage, failure, log and finish shown, and manual starts refused while it runs.

- `jobs.py`: `STAGE_MODULES["autopilot"] = "video_pipeline.autopilot"`; `stage_command("autopilot", book_or_draft_id, ...)` → `--book slug` for a book, `--draft id` for a string subject. `JobRunner.start` adds `KIDDO_JOB_ID=<job id>` to the child environment.
- `books.py`: `AUTOPILOT_STAGE`, label "autopilot"; `autopilot_run(paths, slug, current_job) -> dict | None` reads the run file and turns `running` into `interrupted` when `current_job` is not its `job_id` (AC-4.3). `stage_status(..., current=None)`: while the run is live, the stage it names shows `running` (and `next_action` "Wait for autopilot").
- `app.py`:
  - `_run_stage` accepts `autopilot` (gate: book data error only). Refused while any job runs (AC-1.2, existing busy rule).
  - Manual starts while autopilot runs are refused by the busy rule already (FR-3); also `script_job_running` (script edits, Mark as reviewed) and `approve_audio` refuse while an autopilot job runs for this book, so a person cannot change the script under it.
  - `stop_job`: after `runner.stop()`, if the job was `autopilot` and its run file is still `running`, write `stopped` (covers SIGKILL). Redirect to the book (or the draft while there is no book yet).
  - `last_job` default stages include `autopilot`; the book page also looks up the run's job by `job_id` (a run started from a draft is recorded under the draft id).
  - `create_app`: mark every `running` run file `interrupted` (one studio per project, so none can be live).
- `book.html`: an Autopilot panel at the top of the rail: Run autopilot (or "Resume autopilot" after `failed`/`stopped`/`interrupted`), state badge, current or failed stage with reason, the job log (existing `job_log` macro), and when `finished`: "Finished by autopilot at <time>" with links to the video page and the editions (AC-2.3).
- Tests: `test_run_autopilot_starts_one_autopilot_job` (`("autopilot", slug, False)`); `test_run_autopilot_refused_while_busy_naming_the_job`; `test_manual_stage_refused_while_autopilot_runs`; `test_script_edit_and_approve_refused_while_autopilot_runs`; `test_stop_ends_the_run_and_marks_it_stopped`; `test_running_run_shows_its_stage_running`; `test_failed_run_shows_stage_reason_and_log`; `test_failed_run_offers_resume`; `test_finished_run_says_finished_by_autopilot_with_links`; `test_running_run_file_without_live_job_is_interrupted`; `test_studio_start_marks_running_runs_interrupted`; `test_job_env_carries_the_job_id` (`test_studio_jobs.py`).

### Phase 4: Autopilot from the Add book page
**Implements:** FR-1 · **Satisfies:** AC-1.1 · **Files:** `video_pipeline/studio/app.py`, `video_pipeline/studio/templates/add_book.html`, `video_pipeline/studio/templates/draft.html`, `tests/test_studio_story.py`

Goal: choosing an idea with Autopilot on (checked by default) writes the draft and then creates and finishes the book without the draft review stop.

- `add_book.html`: `<label class="check"><input type="checkbox" name="autopilot" value="1" checked> Autopilot: finish the book without stopping</label>` in the choose-idea form.
- `write_book`: with `autopilot == "1"`, start `("autopilot", draft_id)` instead of `("blueprint", draft_id)` (same busy refusal and draft discard on refusal); without it, today's flow. Redirect to the draft page.

- Tests (`StoryCommands` gains an `autopilot` branch that prints only): `test_autopilot_checkbox_is_on_by_default`; `test_choosing_an_idea_with_autopilot_starts_the_autopilot_job`; `test_choosing_an_idea_without_autopilot_starts_the_blueprint_job`; `test_autopilot_refused_while_busy_discards_the_new_draft`; `test_stop_during_autopilot_story_marks_the_draft_interrupted`; `test_draft_page_links_the_book_once_created`.
